# 客货邮融合项目产品架构蓝图

> 把客货邮融合发展项目从一个“汇报材料集合”升级为可持续迭代的数字产品体系。

## 总体定位

构建 **“知识→能力→产品→服务”** 四层闭环：

```
┌─────────────────────────────────────────────────────────────┐
│  服务层（Service）                                            │
│  咨询辅导 │ 标准制定 │ 培训认证 │ 评审评估 │ 申报辅导          │
├─────────────────────────────────────────────────────────────┤
│  产品层（Product）                                            │
│  门户网站 │ 客货邮Agent │ 政策/标准Skill │ 数据仪表盘          │
├─────────────────────────────────────────────────────────────┤
│  能力层（Capability）                                         │
│  知识图谱 │ 标准库 │ 政策库 │ 案例库 │ 模型库 │ 工具链         │
├─────────────────────────────────────────────────────────────┤
│  数据层（Data）                                               │
│  政策原文 │ 汇报材料 │ 标准规范 │ 案例素材 │ 运行数据         │
└─────────────────────────────────────────────────────────────┘
```

## 四层产品架构

### 第一层：网站展示层（Website Portal）

**定位**：对外品牌窗口与知识发布平台。

**核心模块**：
- **首页**：项目定位、核心价值、最新动态
- **政策中心**：国家/省/市客货邮政策汇编与解读
- **标准体系**：GS1、SSCC、冷藏仓标准、平台技术要求
- **案例展厅**：平顶山实践、郏县/鲁山试点、可复制模板
- **能力服务**：咨询辅导、培训认证、评审评估、申报辅导
- **数据看板**：节点覆盖、线路运营、业务量、绩效指标（脱敏展示）

**技术栈建议**：
- 静态站点：Next.js / Vite + React + Tailwind CSS
- 部署：CloudStudio / Vercel / 自有服务器
- 内容管理：Markdown + Git 驱动（Docs-as-Code）

---

### 第二层：Agent应用层（Intelligent Agent）

**定位**：客货邮领域的智能助手，服务政府、企业、农户、专家四类用户。

**核心 Agent**：

| Agent | 服务对象 | 核心能力 |
|---|---|---|
| **政策通** | 政府部门/企业 | 政策问答、文件解读、申报提醒、验收清单生成 |
| **方案师** | 市县交通局/企业 | 根据本地资源生成客货邮融合实施方案 |
| **标准匠** | 标准化人员 | GS1/SSCC/GLN 编码指导、标签生成、标准符合性检查 |
| **冷链管家** | 园区/农户/合作社 | 冷藏仓调度、温控监测、农产品上行方案 |
| **评审官** | 评审专家 | 按政策标准对申报材料进行预评审、打分、提建议 |
| **数据眼** | 运营人员 | 运行监测、异常预警、绩效分析、可视化报告 |

**技术栈建议**：
- 大模型：主流 LLM + RAG
- 知识库：向量数据库 + 结构化知识图谱
- 工具调用：MCP / Function Calling
- 部署：WorkBuddy Agent / 独立服务

---

### 第三层：Skill工具层（Reusable Skills）

**定位**：把客货邮专家能力封装为可复用的 WorkBuddy Skill，供自己和其他用户调用。

**核心 Skill**：

| Skill | 功能 | 触发词 |
|---|---|---|
| `kehuoyou-policy` | 查询/解读客货邮政策 | “客货邮政策” |
| `kehuoyou-standard` | 查询 GS1/SSCC/GLN 标准 | “SSCC怎么编” |
| `kehuoyou-plan` | 生成客货邮实施方案 | “给我写个客货邮方案” |
| `kehuoyou-ppt` | 基于材料生成/优化PPT | “生成客货邮汇报PPT” |
| `kehuoyou-eval` | 评审材料预检查 | “评审这份客货邮材料” |
| `kehuoyou-coldchain` | 冷藏仓方案设计 | “设计移动冷藏仓方案” |

**技术栈建议**：
- Skill 规范：WorkBuddy Skill 格式（SKILL.md + 脚本/配置）
- 存储：~/.workbuddy/skills/kehuoyou-*/
- 版本：Git 管理，语义化版本

---

### 第四层：CI/CD数据层（Data & Pipeline）

**定位**：知识库的“血液循环系统”，确保内容持续更新、版本可追溯、产品自动构建。

**核心能力**：
- **版本管理**：Git 仓库管理所有知识资产
- **内容提取**：自动从 Office/PPT/PDF 提取文本
- **知识图谱构建**：从文本中抽取实体、关系、事件
- **向量索引**：构建可检索的语义知识库
- **自动构建**：Markdown → 网站 / Agent 知识库 / Skill 配置
- **质量校验**：链接检查、内容完整性检查、标准符合性检查
- **发布流水线**：推送到网站、更新 Agent、发布 Skill

**技术栈建议**：
- 版本控制：Git + GitHub/GitLab
- 内容提取：Python + python-docx/python-pptx/pymupdf
- 知识图谱：Neo4j / 轻量 JSON-LD
- 向量库：Chroma / Qdrant / Pinecone
- 流水线：GitHub Actions / 自研脚本
- 部署：CloudStudio / 自有服务器

## 标准体系映射

| 标准层级 | 标准/规范 | 应用场景 |
|---|---|---|
| 国际标准 | GS1 全球统一编码体系 | 商品/物流单元/位置编码 |
| 国家标准 | GB/T 18127、GB/T 31005、GB/T 29544 | SSCC编码、带板运输、周转箱 |
| 团体标准 | 冷藏仓规范化使用全国团体标准 | 移动冷藏仓设计运营 |
| 省级文件 | 豫交规〔2025〕17号及7个附件 | 建设运营、验收、平台技术要求 |
| 市级文件 | 平交文〔2026〕3号 | 本地节点任务与线路目标 |

## 最小可行产品（MVP）

**第一阶段（1-2周）**：
1. 静态网站骨架上线，展示政策、案例、服务。
2. 第一个 Agent“政策通”可回答豫交规〔2025〕17号相关问题。
3. 第一个 Skill“客货邮政策速查”封装完成。
4. Git 仓库初始化，Markdown 内容源管理。

**第二阶段（1个月）**：
1. 网站增加数据看板、案例展厅。
2. Agent 扩展为“方案师”，可生成实施方案。
3. Skill 扩展为“标准匠”“评审官”。
4. 建立自动构建流水线。

**第三阶段（3个月）**：
1. 网站与运行数据对接（脱敏）。
2. Agent 支持多轮对话和复杂方案设计。
3. Skill 发布到 WorkBuddy 市场。
4. 形成可对外输出的咨询/培训/评审服务。
